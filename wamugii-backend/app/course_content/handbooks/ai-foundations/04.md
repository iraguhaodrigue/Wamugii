A hospital manager says to a data team: "We want AI to help with patients who miss appointments." That sentence could lead to very different projects:

- Predict **whether** each patient will miss their next appointment (yes or no).
- Predict **how many** patients will miss appointments next week (a number).
- Find **groups** of patients with similar missing patterns (groups with no labels).
- **Write** reminder messages in Kinyarwanda and English (new text).

Each version needs different data, different methods and a different way of measuring success. Choosing the wrong one wastes weeks of work. That is why professionals always start with one question: **what kind of output do we need?**

## Why problem type comes first

The problem type decides almost everything that follows:

| Decided by the problem type | Example difference |
|---|---|
| The **data** you collect | Classification needs examples with category labels; regression needs examples with true numbers |
| The **method** you use | A classifier, a regression model, a clustering algorithm, a language model… |
| How you **measure** success | Accuracy, precision and recall for classification; average error for regression (Chapter 14) |
| How the result is **used** | A yes/no alert, a forecast on a dashboard, a list of groups, a draft message |

:::key Key idea
Before asking "which AI tool should we use?", ask "**what output do we need, and what decision will it support?**" The answer tells you the problem type.
:::

## The seven main problem types

| Type | Output | Real example |
|---|---|---|
| **Classification** | A category from a fixed list | Is this MoMo transaction *fraud* or *normal*? Is this cassava leaf *healthy*, *mosaic disease* or *brown streak*? |
| **Regression** | A number | What will this house in Kicukiro sell for? How many litres of milk will the cooperative collect next week? |
| **Clustering** | Groups that form naturally, with no labels given | Group customers by buying habits so you can market to each group |
| **Recommendation** | A ranked list of items for one person | Which videos, products or courses to show this user next |
| **Anomaly detection** | A flag: "this is unusual" | A strange login, a broken machine sensor, an unusual electricity bill |
| **Generation** | New content: text, images, audio, code | Write a product description; draw an illustration; translate a letter |
| **Sequential decision-making** | A series of actions over time | A robot finding its way; a game-playing agent; traffic-light control |

Let us look at each one more closely.

### Classification

The answer is a **label** from a list that is fixed in advance.

- **Binary classification** has **two** classes: fraud or normal, spam or not spam, pass or fail.
- **Multi-class classification** has **more than two**: healthy, mosaic disease or brown streak; or which of 10 digits is written in an image.
- **Multi-label classification** allows **several labels at once**: a news article can be about *politics* and *economy* at the same time.

Classifiers often give a **probability** for each class ("82% fraud") and the system then applies a rule, such as "flag if above 70%".

### Regression

The answer is a **number** on a continuous scale: a price, a temperature, a yield in tonnes, a delivery time in minutes. Note that the word "regression" here has nothing to do with going backwards; it is just the statistics name for predicting numbers.

### Clustering

There are **no labels**. The system groups similar examples together, and people then interpret the groups. You will study clustering in Chapter 10.

### Recommendation

The system **ranks** items for a particular person, using what they and similar people liked before. Recommendation drives YouTube, TikTok, online shops and music apps. It often mixes several methods behind the scenes.

### Anomaly detection

The system learns what **normal** looks like and flags what is far from normal. It is useful when the unusual events (fraud, faults, attacks) are **rare** and you may not have many labelled examples of them.

### Generation

The system creates **new content**. Large language models and image generators are generative systems (Chapter 17). Generation is judged differently from the other types, often by human review, because there is no single correct answer.

### Sequential decision-making

The system chooses **actions over time**, where each action changes the next situation. Search and planning (Chapter 5) and reinforcement learning (Chapter 11) handle this type.

## Classification vs. regression: the classic pair

The quickest test: **is the answer a category or a quantity?**

- "Will this student pass or fail?" → category → **classification**.
- "What mark will this student get out of 100?" → number → **regression**.

The **same situation** can often be framed either way. A bank can ask:

- "Will this loan be repaid, yes or no?" (classification), or
- "How much of this loan will be repaid?" (regression).

Neither is automatically correct. The right framing depends on **the decision** the business must make. If the bank must simply approve or reject, a yes/no prediction fits. If it must set an interest rate or a loan size, a number is more useful.

:::mistake Common mistake
Calling a problem "regression" because the label is **stored as a number**. If grades are stored as 1 = pass and 0 = fail, the problem is still **classification**, because 1 and 0 are just codes for two categories. Ask what the number **means**, not how it is stored.
:::

## Supervised and unsupervised: a first look

You will study these properly in Week 2, but here is the link to problem types:

- If you have **examples with the correct answers** (past transactions already marked fraud or normal), you can learn **supervised** classification or regression.
- If you have data **without answers** and want the computer to find structure (customer groups), it is **unsupervised**, as in clustering.
- If an agent learns by **trying actions and receiving rewards**, it is **reinforcement learning**, suited to sequential decisions.

## A quick decision guide

When you meet a new problem, walk through these questions in order and stop at the first "yes":

1. Do you need **new content** (text, images, audio, code)? → **Generation**.
2. Do you need to **choose actions over time**, where each action changes the next situation? → **Sequential decision-making**.
3. Is the answer a **category** from a fixed list? → **Classification**.
4. Is the answer a **number**? → **Regression**.
5. Do you have **no answers** and want to find **natural groups**? → **Clustering**.
6. Do you want to flag **rare, strange cases**? → **Anomaly detection**.
7. Do you want to **rank items for a person**? → **Recommendation**.

:::example Worked example: using the decision guide
**"Estimate tomorrow's maximum temperature in Huye."** Not new content; not a series of actions; not a category; it is a number → **regression**.

**"Decide if an email is spam."** Not generation; not sequential; the answer is one of two categories → **binary classification**.

**"Group 10,000 farmers by the crops they grow and their yields."** No categories are given in advance and the aim is to find groups → **clustering**.

**"Write a thank-you message for a customer."** New content → **generation**.

**"Find unusual electricity use in a factory."** Flag rare, strange cases → **anomaly detection**.

**"Suggest courses a student might like next."** Rank items for a person → **recommendation**.
:::

## Real systems combine several types

Large products are rarely just one type. A ride-hailing app may:

- **predict** the trip time and price (regression),
- **detect** fraudulent accounts (classification and anomaly detection),
- **match** riders and drivers and plan routes (search and sequential decisions),
- **recommend** pickup points (recommendation),
- and use a chatbot for support (generation).

When you analyse a product, list each **feature** separately and give each one its own problem type.

:::rwanda In Rwanda
Think of a cooperative selling milk in Nyagatare. "How many litres will we collect next week?" is regression and helps plan transport. "Which members are likely to stop supplying?" is classification and helps managers visit them early. "Which members have similar supply patterns?" is clustering and helps design fair payment schedules. One business, three problem types, three different projects.
:::

## Summary

- Always ask **"what output do we need?"** first. The problem type decides the data, method, measure and use.
- **Classification** gives a category (binary, multi-class or multi-label). **Regression** gives a number.
- **Clustering** finds groups without labels. **Recommendation** ranks items for a person. **Anomaly detection** flags rare, strange cases.
- **Generation** creates new content. **Sequential decision-making** chooses actions over time.
- The same situation can be framed in different ways; choose the framing that fits the decision. Real products combine several types.

## Key terms

- **Classification** — predicting a category from a fixed list.
- **Binary classification** — classification with exactly two classes.
- **Multi-class classification** — classification with more than two classes, where each example gets one.
- **Regression** — predicting a number on a continuous scale.
- **Clustering** — grouping similar examples without given labels.
- **Recommendation** — ranking items for a particular person.
- **Anomaly detection** — finding rare examples that are far from normal.
- **Generation** — creating new content such as text, images, audio or code.
- **Sequential decision-making** — choosing a series of actions where each action affects the next situation.

## Think deeper

1. A school wants to "use AI for exam results". Write two different problem framings, one classification and one regression, and say what decision each would support.
:::answer
Classification: "Will this student pass the national exam, yes or no?" This supports deciding which students to place in extra support classes. Regression: "What score out of 100 will this student get?" This supports more detailed planning, such as setting individual targets or estimating how many students will reach the grade needed for a university programme.
:::
2. Exam grades are stored as A, B, C, D, E. Is predicting the grade classification or regression? Explain any complication.
:::answer
It is usually treated as multi-class classification, because the answer is one of five fixed categories. The complication is that the categories have an order (A is better than B), so predicting B when the truth is A is a smaller mistake than predicting E. Some teams therefore treat it as a special "ordinal" problem, or predict the underlying mark (regression) and convert it to a grade.
:::
3. Why might a bank use anomaly detection instead of classification to find a brand-new type of fraud?
:::answer
Classification needs many labelled examples of each class. A brand-new fraud trick has few or no labelled examples yet, so a classifier trained on old fraud may not recognise it. Anomaly detection only needs to learn what normal behaviour looks like, and it can flag anything that looks very different, including new tricks nobody has labelled yet.
:::
