How does a maps app find the fastest way from Kigali to Rubavu out of thousands of possible roads? How does a computer schedule hundreds of exams so that no student has two at the same time? How did a chess computer beat the world champion in 1997?

All three use one of the oldest ideas in AI: **search**. The computer imagines possible steps, explores where they lead, and picks a good path to the goal. In this chapter you will run search methods by hand on a small map of Rwanda, so you can see exactly how they think.

## Many problems are search problems

Finding a route, solving a puzzle, planning a delivery round, scheduling exams and choosing a chess move all share one shape:

- there is a **starting situation**,
- there is a **goal**,
- and there are many possible **steps** in between.

The computer must search through the possible steps for a path that reaches the goal, ideally the cheapest one.

## The parts of a search problem

| Part | Meaning | Route example |
|---|---|---|
| **State** | A description of the situation | "The bus is in Muhanga" |
| **Initial state** | Where we start | Kigali |
| **Actions** | What we can do from a state | Drive to a neighbouring town |
| **Transition** | The state an action leads to | Driving Kigali → Muhanga puts us in Muhanga |
| **Goal test** | How we know we are done | Are we in Rubavu? |
| **Path cost** | What a path costs | Total kilometres (or time, or fuel) |

All the states and the actions between them form the **state space**, usually drawn as a **graph**: states are dots (nodes) and actions are lines (edges) with costs.

[[fig:searchmap|A small, simplified map for our examples. Numbers on the roads are distances in km. The h values are straight-line estimates of the distance left to Rubavu, used later by A-star.]]

The distances are simplified to make the arithmetic easy, but the shape is realistic: two routes lead from Kigali to Rubavu, one through Musanze and one through Muhanga and Ngororero.

## Uninformed search: no hints

"Uninformed" means the method has **no idea** which direction the goal is. It only knows the map's connections and costs.

### Breadth-first search (BFS)

BFS explores in **layers**: first every place **one** step away, then every place **two** steps away, and so on, like ripples spreading on water.

On our map (neighbours taken in alphabetical order):

1. Start at Kigali.
2. Layer 1: Muhanga, Musanze.
3. Layer 2: from Muhanga, Ngororero; from Musanze, **Rubavu**: goal found.

BFS returns **Kigali → Musanze → Rubavu** (2 steps, 155 km).

- **Guarantee:** BFS finds the path with the **fewest steps**.
- **Weakness:** it keeps every place of the current layer in memory, which becomes huge for big problems. And fewest steps is not always cheapest: if one road were very long, BFS would not notice.

### Depth-first search (DFS)

DFS follows **one road as far as it can**, then backs up and tries another.

On our map: Kigali → Muhanga (first alphabetically) → Ngororero → **Rubavu**. Goal found.

DFS returns **Kigali → Muhanga → Ngororero → Rubavu** (3 steps, **180 km**), a worse path than BFS found.

- **Strength:** uses very little memory, because it only remembers the current path.
- **Weakness:** may find a long, poor path first, and in very deep or endless spaces it can get lost going down one branch forever.

### Uniform-cost search (UCS)

UCS always expands the path that is **cheapest so far**. It keeps a list of places it can reach (the **frontier**) with their costs, and always takes the cheapest one next.

:::example Worked example: uniform-cost search, step by step
| Step | Expand (cost so far) | Frontier after this step |
|---|---|---|
| 1 | Kigali (0) | Muhanga 50, Musanze 90 |
| 2 | Muhanga (50) | Musanze 90, Ngororero 95 |
| 3 | Musanze (90) | Ngororero 95, Rubavu 155 |
| 4 | Ngororero (95) | Rubavu 155 (the route via Ngororero would cost 180, which is worse, so it is ignored) |
| 5 | Rubavu (155) | Goal reached |

Result: **Kigali → Musanze → Rubavu, 155 km**, and it is guaranteed to be the cheapest path. UCS expanded **5** places.
:::

Notice an important rule: UCS stops when it **takes the goal out of the frontier to expand it**, not when it first **sees** the goal. That is what guarantees the cheapest path, because by then every cheaper option has been checked.

## Informed search: using a hint

A **heuristic** is a quick **estimate** of how far a state is from the goal. On a map, a good heuristic is the **straight-line distance** ("as the crow flies") to the destination. It is easy to compute, and it can never be more than the real road distance, because roads bend.

A heuristic that **never overestimates** the real remaining cost is called **admissible**. Our h values are admissible: for example h(Musanze) = 55 while the real road distance left is 65.

### A-star search (A*)

A-star ranks each option on the frontier by:

> **f = g + h**: cost so far (**g**) plus estimated cost still to go (**h**)

It always expands the option with the smallest **f**. In plain words, it prefers paths that are both cheap so far **and** look close to the goal.

:::example Worked example: A-star search, step by step
| Step | Expand | g | h | f = g + h | Frontier after this step (f) |
|---|---|---|---|---|---|
| 1 | Kigali | 0 | 120 | 120 | Musanze 145, Muhanga 150 |
| 2 | Musanze | 90 | 55 | 145 | Muhanga 150, Rubavu 155 |
| 3 | Muhanga | 50 | 100 | 150 | Rubavu 155, Ngororero 155 |
| 4 | Rubavu | 155 | 0 | 155 | Goal reached |

How each f was calculated: Musanze = 90 + 55 = 145. Muhanga = 50 + 100 = 150. Rubavu (via Musanze) = 155 + 0 = 155. Ngororero (via Muhanga) = 95 + 60 = 155. When two options tie, we take the goal.

Result: **Kigali → Musanze → Rubavu, 155 km**, the same cheapest path as UCS, but A-star expanded only **4** places instead of 5.
:::

Look at step 1. The first road to Musanze is **longer** (90 km against 50 km to Muhanga), yet A-star explores Musanze first, because Musanze is much closer to Rubavu. That is the power of combining real cost with a good estimate. On a real map with thousands of towns, this saving becomes enormous: A-star ignores most of the map that points in the wrong direction.

### Why admissibility matters

If the heuristic **never overestimates**, A-star is guaranteed to find the cheapest path. If the heuristic **overestimates** (for example, it wrongly says Musanze is 500 km from Rubavu), A-star may be misled into a worse route and stop with it.

Two extreme cases help you understand h:

- If **h = 0** everywhere, A-star becomes uniform-cost search: safe but slower.
- If **h were exactly the true remaining cost**, A-star would walk straight to the goal without any wrong turns.

Good heuristics sit in between: cheap to compute, never too high, and as close to the truth as possible.

:::mistake Common mistake
Stopping A-star (or UCS) the moment the goal **appears** on the frontier. In step 2 above, Rubavu appeared with f = 155, but Muhanga (f = 150) still looked cheaper and had to be checked first. Only when the goal is **chosen for expansion** is the answer guaranteed to be the cheapest.
:::

## Comparing the methods

| Method | Uses a heuristic? | Guarantees | Main weakness |
|---|---|---|---|
| Breadth-first | No | Fewest steps | Large memory; ignores road lengths |
| Depth-first | No | Nothing about quality | Can find long paths or get lost |
| Uniform-cost | No | Cheapest path | Explores in all directions |
| A-star | Yes | Cheapest path (if h is admissible) | Needs a good heuristic |

## Search in games: minimax

In a two-player game such as chess or draughts, your opponent fights back. **Minimax** search assumes the opponent always chooses the move that is **worst for you**, and you choose the move whose **worst case is best**.

:::example Worked example: minimax with three moves
You can play move A, B or C. For each, your opponent has two replies. The numbers show how good the final position is for you (higher is better).

| Your move | Opponent reply 1 | Opponent reply 2 | Worst case for you |
|---|---|---|---|
| A | 3 | 12 | 3 |
| B | 8 | 2 | 2 |
| C | 14 | 5 | 5 |

A careless player chases the biggest number (14, under C) or (12, under A). Minimax looks at the worst case of each move and chooses **C**, because 5 is the best guaranteed result.
:::

Real games have far too many positions to search to the end, so programs search a few moves ahead and use an **evaluation function** (a kind of heuristic) to score positions. Deep Blue (Chapter 2) combined minimax-style search with an expert-written evaluation function and very fast hardware. AlphaGo later replaced hand-written evaluation with a neural network that **learned** to judge positions.

:::rwanda In Rwanda
Search powers everyday services here: route planning in maps and ride-hailing apps, delivery rounds for e-commerce and pharmacies, flight planning for medical drones, and timetabling for schools and universities. Scheduling problems (no student with two exams at once, no room double-booked) are search over a huge space of possible timetables.
:::

## Summary

- A **search problem** has states, an initial state, actions, a goal test and a path cost. Together they form the state space.
- **Breadth-first** finds the fewest steps; **depth-first** uses little memory but may find poor paths; **uniform-cost** finds the cheapest path.
- A **heuristic** estimates distance to the goal. An **admissible** heuristic never overestimates.
- **A-star** expands the smallest **f = g + h**. With an admissible heuristic it finds the cheapest path while exploring far less.
- **Minimax** chooses the move with the best worst-case result in two-player games.

## Key terms

- **State space** — all possible states and the actions linking them.
- **Frontier** — the places a search has discovered but not yet expanded.
- **Breadth-first search** — explores all places one step away, then two steps away, and so on.
- **Depth-first search** — follows one path as deep as possible before backing up.
- **Uniform-cost search** — always expands the cheapest path found so far.
- **Heuristic** — a quick estimate of the remaining cost to the goal.
- **Admissible heuristic** — a heuristic that never overestimates the real remaining cost.
- **A-star search** — expands the option with the smallest f = g + h.
- **Optimal** — guaranteed to find the best (cheapest) solution.
- **Minimax** — game search that assumes the opponent plays their best and picks the move with the best worst case.

## Think deeper

1. Why does A-star with an admissible heuristic usually explore fewer states than uniform-cost search, while still finding the cheapest path?
:::answer
Uniform-cost search only looks at the cost so far, so it spreads out in every direction, including directions that lead away from the goal. A-star adds the estimate h of the remaining cost, so paths heading away from the goal get a large f and are pushed to the back of the queue. Because h never overestimates, A-star never wrongly rejects the true cheapest path; it simply avoids wasting time on clearly worse directions.
:::
2. A student uses "h = 3 × straight-line distance" as a heuristic to make A-star faster. What risk does this create?
:::answer
Three times the straight-line distance will often be larger than the real remaining road distance, so the heuristic is no longer admissible. A-star may then be pushed away from the truly cheapest route and stop with a more expensive path. It may run faster, but the guarantee of finding the cheapest path is lost.
:::
3. In the minimax example, why is choosing move A because of its 12 a bad idea?
:::answer
The 12 only happens if the opponent chooses reply 2, which is good for you. A sensible opponent will choose reply 1, giving you only 3. Minimax assumes the opponent plays well, so it compares the guaranteed (worst-case) results: 3 for A, 2 for B and 5 for C. Move C is the safest strong choice.
:::
