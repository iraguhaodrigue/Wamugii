A traffic light, a delivery drone, a chatbot and a doctor seem to have nothing in common. Yet AI researchers describe all of them with the same simple picture: something that **senses** the world and **acts** on it. This picture is called an **agent**, and it is one of the most useful ideas in the whole field. Once you can describe a system as an agent, you can ask sharp questions about it: What does it sense? What can it do? How do we judge it? How hard is its world?

This chapter gives you a professional toolkit for answering those questions.

## What is an agent?

An **agent** is anything that **perceives** its environment through **sensors** and **acts** upon that environment through **actuators**.

[[fig:agent|An agent receives percepts from its environment through sensors, decides, and changes the environment through actuators. Then the loop repeats.]]

| Agent | Sensors (how it perceives) | Actuators (how it acts) |
|---|---|---|
| A person | Eyes, ears, skin | Hands, legs, voice |
| A self-driving car | Cameras, radar, GPS, speed sensors | Steering, accelerator, brakes, indicators |
| A chatbot | The text you type (and sometimes images or voice) | The reply it writes; sometimes actions such as booking an appointment |
| A smart thermostat | Temperature and motion sensors | Switching heating or cooling on and off |
| A fraud-detection system | Details of each transaction | Approve, block, or ask for extra confirmation |

Notice that a sensor does not have to be physical. For software agents, the "sensors" are simply the data they receive.

### Percepts and the agent function

A **percept** is what the agent senses at one moment: one camera frame, one message, one transaction. The **percept sequence** is everything the agent has perceived so far.

The **agent function** is the rule that maps a percept sequence to an action. In plain words: *given everything I have seen so far, what should I do now?* The **agent program** is the actual code or model that carries out that function inside a machine.

## Rational agents

The goal of AI, in this view, is to build **rational agents**.

> A **rational agent** chooses the action that is **expected** to give the best result, according to its performance measure, given what it has perceived and what it knows.

Three words in that definition matter a lot:

- **Expected.** The agent cannot see the future. It chooses what is most likely to turn out well.
- **Performance measure.** "Best" is defined by how we judge success, not by the agent's own wishes.
- **What it knows.** An agent can only use the information it has.

So **rational does not mean perfect**. A careful doctor who has not yet received a blood test result may give the best treatment based on symptoms and still be wrong. That doctor acted rationally. Being rational also includes **gathering information** when it is useful: looking both ways before crossing the road is rational, because it improves the decision.

:::key Key idea
Judge an agent by its **expected** results given its information, not by luck. A rational agent can be wrong; a lucky agent can be right for bad reasons.
:::

## Specifying an agent with PEAS

Before engineers build an agent, they describe its task with four questions, remembered as **PEAS**:

| Letter | Question | Example: a medical-delivery drone in Rwanda |
|---|---|---|
| **P**erformance measure | How do we judge success? | Deliveries on time, zero accidents, packages undamaged, battery and cost per flight |
| **E**nvironment | Where does it work? | Hills, wind, rain, airspace shared with aircraft, hospital drop zones |
| **A**ctuators | How does it act? | Motors and control surfaces, parachute release, radio messages to operators |
| **S**ensors | How does it perceive? | GPS, cameras, airspeed and wind sensors, battery monitor |

### Why the performance measure comes first

Getting the **performance measure** right is the most important step, because a well-built agent will chase exactly what you measure. This is sometimes summed up as **"what you measure is what you get"**.

- Reward a drone only for **speed**, and it may fly in dangerous weather.
- Judge a customer-service chatbot only by **how quickly conversations end**, and it may learn to give short, unhelpful answers so customers give up.
- Judge a social-media feed only by **time spent watching**, and it may push extreme or upsetting content because it holds attention.

Good performance measures usually combine several goals (speed **and** safety **and** cost) and describe the outcome you actually want in the world.

:::mistake Common mistake
Writing a performance measure that describes **activity** instead of **results**: "the chatbot answers many messages" instead of "customers' problems are solved correctly". Activity is easy to count but often not what matters.
:::

## Kinds of environments

The environment decides how hard an agent is to build. Engineers classify it on five properties. For each row, the right-hand side is harder.

| Property | Easier side | Harder side |
|---|---|---|
| **Observable** | **Fully observable**: the agent can see everything it needs (a chess board) | **Partially observable**: some things are hidden (a driver cannot see round a corner; a doctor cannot see inside the body) |
| **Outcome** | **Deterministic**: the same action in the same state always gives the same result (moving a chess piece) | **Stochastic**: chance plays a part (weather, other people, machine faults) |
| **Time** | **Episodic**: each decision stands alone (sorting photos one by one) | **Sequential**: today's action changes tomorrow's options (driving, investing, a conversation) |
| **Change** | **Static**: the world waits while the agent thinks (a crossword) | **Dynamic**: the world keeps moving (traffic, markets) |
| **Agents** | **Single-agent**: the agent works alone (solving a puzzle) | **Multi-agent**: others act too, helping or competing (football, auctions, roads) |

:::example Worked example: classifying two environments
**A system that sorts photos of cassava leaves into healthy or diseased.**
- Observable: mostly **fully observable**; everything needed should be in the photo (though a blurry photo hides details).
- Outcome: **deterministic**; labelling a photo does not change the photo.
- Time: **episodic**; each photo is a separate decision.
- Change: **static**; the photo does not change while the system thinks.
- Agents: **single-agent**.
This is a relatively easy environment, which is one reason image classification became a success story early.

**A self-driving car in Kigali traffic.**
- **Partially observable**: pedestrians behind buses, blind corners, other drivers' intentions.
- **Stochastic**: rain, a motorbike that suddenly turns.
- **Sequential**: every decision changes the next situation.
- **Dynamic**: traffic keeps moving while the car decides.
- **Multi-agent**: drivers, motorbike taxis, cyclists and pedestrians all act.
It is on the hard side of **every** row, which is why self-driving cars remain one of the hardest problems in AI.
:::

## Types of agents

Agent designs range from very simple to very capable. Each type adds one ability to the one before.

1. **Simple reflex agent.** Reacts only to the **current** percept, using condition-action rules: *if the room is dark, turn on the light*. Fast and simple, but it fails when the right action depends on things it cannot currently see.
2. **Model-based reflex agent.** Keeps an **internal model** (a memory or picture) of the world, so it can handle partial observability. A car remembers that a pedestrian walked behind a bus a second ago.
3. **Goal-based agent.** Has a **goal** and plans actions to reach it: *reach the hospital*. It can consider "what will happen if I do this?" This is where **search** and **planning** come in (Chapter 5).
4. **Utility-based agent.** Compares **how good** different outcomes are, using a utility (a score of desirability): reach the hospital **fast, safely and cheaply**. Useful when goals conflict or when outcomes are uncertain.
5. **Learning agent.** Improves its own behaviour from experience. It has a part that acts and a part that learns from feedback on how well it is doing. Any of the four types above can be made into a learning agent.

:::example Worked example: one task, five agents
Task: managing the lights in a school corridor.
- **Simple reflex:** turn lights on when the motion sensor detects movement.
- **Model-based:** remember that people entered and have not left, so keep the lights on even when they stand still.
- **Goal-based:** goal "corridor lit whenever occupied"; plans when to switch.
- **Utility-based:** balance comfort, electricity cost and bulb life; dim the lights at quiet times.
- **Learning:** learns the school timetable from weeks of data and switches on just before break time.
:::

:::rwanda In Rwanda
Mobile-money fraud detection is a good example of a **utility-based learning agent**. It compares the cost of blocking a real customer (annoyance, lost business) with the cost of letting fraud through (stolen money), and it keeps learning as fraudsters change their tricks. Its environment is partially observable (it cannot see the fraudster), stochastic, sequential and multi-agent, because criminals actively adapt to it.
:::

## Summary

- An **agent** perceives through **sensors** and acts through **actuators**. Every AI system can be described this way.
- A **rational agent** chooses the action with the best **expected** result given its information. Rational is not the same as perfect.
- **PEAS** (Performance measure, Environment, Actuators, Sensors) specifies an agent's task. The **performance measure** is the most important part: what you measure is what you get.
- Environments are classified as observable, deterministic, episodic, static, single-agent, or their harder opposites.
- Agent types: **simple reflex, model-based, goal-based, utility-based** and **learning** agents.

## Key terms

- **Agent** — anything that perceives its environment through sensors and acts on it through actuators.
- **Sensor** — the means by which an agent perceives (a camera, or the data a program receives).
- **Actuator** — the means by which an agent acts (a motor, or a message a program sends).
- **Percept** — what an agent perceives at one moment.
- **Rational agent** — an agent that chooses the action expected to give the best result, given what it knows.
- **PEAS** — Performance measure, Environment, Actuators, Sensors: a way to specify an agent's task.
- **Performance measure** — how an agent's success is judged.
- **Partially observable** — an environment where some needed information is hidden from the agent.
- **Stochastic** — an environment where chance affects the result of actions.
- **Sequential environment** — one where each action affects future situations.
- **Utility-based agent** — an agent that compares how desirable different outcomes are.
- **Learning agent** — an agent that improves its behaviour from experience.

## Think deeper

1. A chess program loses a game because its opponent made a brilliant move it could not foresee. Can the program still be called rational? Explain.
:::answer
Yes, it can. Rational means choosing the move with the best expected result given what the agent knows and can compute. If the program searched well and chose the move that looked best given the information available, it acted rationally even though it lost. Losing shows that it was not perfect, and rational does not mean perfect.
:::
2. Write a bad performance measure and a better one for a school timetable-planning AI. Explain what could go wrong with the bad one.
:::answer
Bad: "number of lessons scheduled per week". The system could pack lessons with no breaks, give a teacher two classes at once in different buildings, or schedule too many lessons in one subject. Better: "every class receives its required hours per subject, no teacher or room is double-booked, no class has more than three lessons in a row without a break, and teachers' travel between rooms is as low as possible". The better measure describes the outcomes people actually want.
:::
3. Classify the environment of a customer-service chatbot for a bank on all five properties.
:::answer
Partially observable: it cannot see the customer's real situation or intentions, only what they type. Stochastic: customers respond unpredictably. Sequential: each reply changes how the conversation continues. Mostly static during one reply, since the customer waits while it answers, though over a longer time the situation can change. Multi-agent in a mild sense: the customer is another agent whose goals may differ, and some users try to trick the bot.
:::
